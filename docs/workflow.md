# 翻訳フロー

`monde` を使った翻訳には、2 つのフローがあります。

- [新規翻訳](#新規翻訳): 原文の Markdown から翻訳ファイル（`.po`）を新しく作り、訳を入れて翻訳済みの Markdown を作ります。
- [原文更新](#原文更新): 原文が更新されたときに、既存の `.po` の訳を引き継ぎ、変わった箇所だけを訳し直します。

この章では、リポジトリにある小さな英語の文書 [`examples/hello.md`](examples/hello.md) を日本語に訳す例で、各段階のコマンド、入力と出力のファイル、確認すべき表示を順に説明します。各サブコマンドのオプションの詳細は [コマンドリファレンス](commands.md) を、初版で対応していない記法は [既知の制限](limitations.md) を参照してください。

## ファイルの役割

| ファイル | 例 | 作るもの | 内容 |
| --- | --- | --- | --- |
| 原文の Markdown | `hello.md` | 文書の保守者 | 翻訳する元の文書 |
| 翻訳テンプレート | `hello.pot` | `monde extract` | 原文から取り出した翻訳する文字列（msgid）の一覧。訳は空 |
| 翻訳ファイル | `hello.ja.po` | `monde init`、`monde update` | 言語ごとの訳（msgstr）を持つファイル。翻訳者が編集する |
| 翻訳済みの Markdown | `hello.ja.md` | `monde translate` | 原文の翻訳する文字列だけを訳に置き換えた文書 |

`.pot` は原文から毎回作り直せる中間のファイルです。翻訳者の作業の成果は `.po` に残るため、`.po` と翻訳済みの Markdown をバージョン管理に置きます（[翻訳済み Markdown の差分レビュー](#翻訳済み-markdown-の差分レビュー) を参照）。

各コマンドは、結果を `-o` で指定したファイル（省略すると標準出力）に書き、統計を標準エラー出力に 1 行で表示します。統計の書式は固定で、件数のところに数が入ります（以下では `N` などで表します）。統計は `-q`（`--quiet`）で抑止できます。警告とエラーは `-q` を指定しても表示されます。

## 新規翻訳

原文をはじめて翻訳するときのフローです。`extract` → `init` → 翻訳者による `.po` の編集 → `translate` の順に進めます。以下のコマンドは、`hello.md` を置いたディレクトリで実行します。

### 1. 翻訳テンプレートを作る（`extract`）

```sh
monde extract --front-matter-keys title -o hello.pot hello.md
```

- 入力: `hello.md`（原文の Markdown）
- 出力: `hello.pot`（翻訳テンプレート）

原文から翻訳する文字列（見出し、段落、リスト項目の中の段落、引用の中の段落など）を取り出し、1 つの文字列を 1 つのエントリとする `.pot` を作ります。コードブロックや HTML ブロックは翻訳の対象になりません。`--front-matter-keys title` は、YAML フロントマターの `title` の値も翻訳の対象にする指定です（[YAML フロントマターの値を翻訳する](#yaml-フロントマターの値を翻訳する) を参照）。

標準エラー出力には次の書式の統計が表示されます。

```text
extract: N messages
```

`N` は `.pot` のエントリの数（ヘッダを除く）です。同じ文字列が文書に何度出てきても 1 つのエントリにまとめられるため、文書の中の出現の数より少ないことがあります。

### 2. 翻訳ファイルを作る（`init`）

```sh
monde init -l ja -o hello.ja.po hello.pot
```

- 入力: `hello.pot`（翻訳テンプレート）
- 出力: `hello.ja.po`（日本語の翻訳ファイル）

`.pot` のすべてのエントリを、訳（msgstr）が空のまま引き継いだ `.po` を作ります。`-l ja` の値はヘッダの `Language` に書かれます。標準エラー出力には次の書式の統計が表示されます。

```text
init: N messages, language L
```

`N` は `.po` のエントリの数、`L` はヘッダに書いた言語コードです。`N` が手順 1 の `extract` の `N` と同じであることを確かめます。

`-l` を省略すると、環境変数 `LC_ALL`、`LC_MESSAGES`、`LANG` の順に見て、最初に設定されている値から言語コードを決めます（`ja_JP.UTF-8` なら `ja_JP`）。このときは、どの環境変数の値を使ったかが `init: using language 'L' from VAR` の書式で表示されます（`VAR` は環境変数の名前）。意図した言語になっていることを確かめてください。

### 3. 翻訳ファイルを編集する（翻訳者の作業）

- 入力: `hello.ja.po`（訳が空の翻訳ファイル）
- 出力: `hello.ja.po`（訳を入れた翻訳ファイル）

`hello.ja.po` の各エントリの msgstr に訳を入れます。Monde 自身は `.po` の編集に関与しません。PO に対応した翻訳プラットフォームやエディタ（Poedit、Lokalize、Emacs の po-mode など）で開いて編集します。これらのツールは未翻訳や fuzzy のエントリを絞り込んで表示でき、エントリに付いたコメント（`#.` の要素の種類、`#:` の原文の位置）で、文字列が原文のどこにあるかを確かめられます。

訳を入れるときは、強調（`*small*`）やリンク（`[GNU gettext](https://...)`）などのインラインの Markdown の記法を、訳文の中でも同じように書きます。msgid の中の改行は、原文の段落の中の改行です。訳文の改行の位置は原文と同じでなくてもかまいません。

### 4. 翻訳済みの Markdown を作る（`translate`）

```sh
monde translate --front-matter-keys title -o hello.ja.md hello.md hello.ja.po
```

- 入力: `hello.md`（原文の Markdown）と `hello.ja.po`（訳を入れた翻訳ファイル）
- 出力: `hello.ja.md`（翻訳済みの Markdown）

原文の翻訳する文字列だけを `.po` の訳に置き換え、それ以外（フロントマターの区切り、見出しやリストの記号、空行、インデント、コードブロック、改行コード）を原文のバイト列のまま残した Markdown を作ります。`--front-matter-keys` には、手順 1 の `extract` と同じ値を指定します。

標準エラー出力には次の書式の統計が表示されます。

```text
translate: A translated, B fuzzy, C untranslated, D missing, E total, P.Q% translated
```

件数は、`.po` のエントリの数ではなく、文書の中で翻訳する文字列が出現する箇所の数です。

| 項目 | 意味 |
| --- | --- |
| `A translated` | 訳のあるエントリで置き換えた箇所 |
| `B fuzzy` | `.po` のエントリが fuzzy の箇所 |
| `C untranslated` | `.po` のエントリの訳が空の箇所 |
| `D missing` | `.po` に対応するエントリがない箇所 |
| `E total` | 翻訳する文字列の箇所の合計（A + B + C + D） |
| `P.Q% translated` | 翻訳率（A ÷ E を百分率で、小数点以下 1 桁） |

すべてを訳し終えていれば、`B`、`C`、`D` が 0 で、翻訳率が `100.0%` になります。`untranslated` と `fuzzy` の箇所は既定で原文のまま出力されます（[未翻訳と fuzzy のエントリの扱い](#未翻訳と-fuzzy-のエントリの扱い) を参照）。`missing` が 0 でないときは、`.po` が原文と合っていない（原文を更新した後に `update` をしていない）か、`extract` と `translate` の `--front-matter-keys` が違う可能性があります。文書に翻訳する文字列が 1 つもないときは、翻訳率の代わりに `translate: no translatable messages` と表示されます。

訳文に空行やブロックを始める記号が含まれるなど、文書の構造を変え得るときは、警告が表示されます。このときも出力は書かれ、終了コードは 0 です。警告が出たら、該当するエントリの訳文を見直してください（詳しくは [既知の制限](limitations.md) を参照）。

## 原文更新

翻訳した後に原文が更新されたときのフローです。更新後の原文で `extract` → `update` で既存の `.po` とマージ → fuzzy と未翻訳のエントリを翻訳 → `translate` の順に進めます。新規翻訳と違い、`init` は使いません。`init` で `.po` を作り直すと、それまでの訳がすべて失われます。

ここでは、[新規翻訳](#新規翻訳) で作った `hello.ja.po` があり、`hello.md` の段落や見出しの一部が書き換えられた、または段落が追加・削除されたものとします。

### 1. 更新後の原文から翻訳テンプレートを作る（`extract`）

```sh
monde extract --front-matter-keys title -o hello.pot hello.md
```

- 入力: `hello.md`（更新後の原文）
- 出力: `hello.pot`（更新後の翻訳テンプレート）

新規翻訳の手順 1 と同じコマンドです。`--front-matter-keys` も前回と同じ値を指定します。統計 `extract: N messages` の `N` は、更新後の原文のエントリの数です。

### 2. 既存の翻訳ファイルとマージする（`update`）

```sh
monde update -o hello.ja.po hello.pot hello.ja.po
```

- 入力: `hello.pot`（更新後の翻訳テンプレート）と `hello.ja.po`（既存の翻訳ファイル）。この順に指定します。
- 出力: `hello.ja.po`（マージした翻訳ファイル）

更新後のテンプレートに、既存の `.po` の訳を引き継ぎます。規則は GNU gettext の `msgmerge --previous` と同じです。

- msgid が変わっていないエントリは、訳をそのまま引き継ぎます。
- msgid が少し変わったエントリは、似た msgid の訳を引き継ぎ、fuzzy の印（`#, fuzzy`）と前回の msgid（`#|` で始まる行）を付けます。翻訳者は前回の msgid と今の msgid の違いを見て、訳を直します。
- 新しく現れた msgid は、訳が空のエントリになります。
- 原文から消えた msgid のうち訳のあったものは、廃止エントリ（`#~` で始まる行）として `.po` の末尾に残します。同じ文字列が原文に戻ったときは、その訳が復活します。訳のなかったものは捨てます。
- ヘッダの `Language`、`PO-Revision-Date`、`Last-Translator` などは既存の `.po` のものを引き継ぎます。

`-o` を省略すると、マージの結果は標準出力に書かれ、既存の `.po` は変わりません。既存の `.po` を更新するには、上の例のように `-o` に既存の `.po` と同じパスを指定します（[既存の翻訳ファイルを上書きする](#既存の翻訳ファイルを上書きする) を参照）。

標準エラー出力には次の書式の統計が表示されます。

```text
update: A matched, B fuzzy, C added, D obsoleted
```

| 項目 | 意味 | 翻訳者がすること |
| --- | --- | --- |
| `A matched` | msgid が完全に一致し、既存のエントリの訳と状態をそのまま引き継いだエントリ（廃止エントリが復活したものを含む） | なし（既存のエントリが未翻訳や fuzzy なら、その状態のまま） |
| `B fuzzy` | 今回のマージで、似た msgid の訳を fuzzy として引き継いだエントリ | 前回の msgid との違いを確かめて訳を直し、fuzzy の印を外す |
| `C added` | 既存の `.po` に対応するものがなく、訳が空で加わったエントリ | 新しく訳す |
| `D obsoleted` | 原文から消えて、廃止エントリにしたエントリ | なし（不要になった訳の控え） |

`A + B + C` は、手順 1 の `extract: N messages` の `N` と同じになります。`B fuzzy` は今回のマージで新しく fuzzy になったエントリの数です。前回までに fuzzy だったエントリが完全一致したときは `matched` に数えられ、fuzzy のまま残ります。`.po` に残っている fuzzy と未翻訳の数は、手順 4 の `translate` の統計か、PO 対応のエディタで確かめます。

似た msgid の訳を流用したくないときは、`--no-fuzzy-matching` を指定します。このときは完全一致だけで訳を引き継ぎ、msgid が変わったエントリは `added`（訳が空）になります。

### 3. fuzzy と未翻訳のエントリを翻訳する（翻訳者の作業）

- 入力: `hello.ja.po`（マージした翻訳ファイル）
- 出力: `hello.ja.po`（訳を直した翻訳ファイル）

新規翻訳の手順 3 と同じく、PO 対応のエディタや翻訳プラットフォームで `hello.ja.po` を開き、fuzzy と未翻訳のエントリを絞り込んで訳します。fuzzy のエントリは、前回の msgid（`#|`）と今の msgid の違いに合わせて訳を直し、fuzzy の印を外します（多くのエディタでは、訳を確定すると印が外れます）。

### 4. 翻訳済みの Markdown を作り直す（`translate`）

```sh
monde translate --front-matter-keys title -o hello.ja.md hello.md hello.ja.po
```

- 入力: `hello.md`（更新後の原文）と `hello.ja.po`（訳を直した翻訳ファイル）
- 出力: `hello.ja.md`（翻訳済みの Markdown）

新規翻訳の手順 4 と同じコマンドです。統計の `fuzzy`、`untranslated`、`missing` が 0 で、翻訳率が `100.0%` であれば、原文の更新に合わせた訳がすべて入っています。手順 3 の途中でも `translate` は実行でき、訳し終えていない箇所は原文のまま出力されます。

## 既存の翻訳ファイルを上書きする

`update` は、出力先（`-o`）に入力の既存の `.po` と同じパスを指定して、その `.po` をそのまま更新できます。

```sh
monde update -o hello.ja.po hello.pot hello.ja.po
```

`monde` はすべての入力を読み終えてから出力を書くため、入力と出力が同じファイルでも既存の内容は失われません。出力先のファイルは確認なしに置き換えられます。

`.pot` や `.po` の構文の誤り、重複するエントリなどでマージに失敗したときは、エラーを表示して終了コード 1 で終了し、既存の `.po` は変更されません。エラーは `<path>:<line>: error: <message>` の書式で、どちらのファイルのどの行かが分かるように表示されます。原因を直してから、同じコマンドをもう一度実行してください。

これは `update` に限らず、すべてのサブコマンドに共通です。処理が失敗したときは、`-o` で指定した出力先のファイルを作成も変更もしません。

## 未翻訳と fuzzy のエントリの扱い

`translate` は既定で、`.po` の訳が空のエントリ（未翻訳）と、fuzzy の印が付いたエントリに対応する箇所を、原文のまま出力します。fuzzy の訳は似た原文の訳を流用した仮のもので、今の原文に合っているとは限らないためです。訳し終えていない `.po` からでも翻訳済みの Markdown を作れ、訳のない箇所は原文の英語のまま残ります。

fuzzy のエントリの訳も使いたいときは、`translate` に `--use-fuzzy` を指定します。fuzzy のエントリのうち訳が空でないものを、訳として採用します。

```sh
monde translate --use-fuzzy --front-matter-keys title -o hello.ja.md hello.md hello.ja.po
```

`translate` の統計の翻訳率（`P.Q% translated`）は、`--use-fuzzy` の有無にかかわらず fuzzy の箇所を翻訳済みに数えません。`--use-fuzzy` で fuzzy の訳を出力に使っても、翻訳率は上がりません。翻訳率が `100.0%` になるのは、fuzzy の印をすべて外し、すべての箇所に訳を入れたときだけです。

## YAML フロントマターの値を翻訳する

既定では、YAML フロントマターは翻訳の対象にならず、原文のまま出力されます。フロントマターの値（`title` など）を翻訳するときは、翻訳するキーのキーパスを `--front-matter-keys` で指定します。

`extract` と `translate` の両方に、同じ `--front-matter-keys` を指定する必要があります。

```sh
monde extract --front-matter-keys title -o hello.pot hello.md
monde translate --front-matter-keys title -o hello.ja.md hello.md hello.ja.po
```

`translate` で `--front-matter-keys` を省略したり、`extract` と違うキーを指定したりすると、そのキーの値は `.po` に訳があっても原文のまま出力されます。`extract` で指定しなかったキーを `translate` で指定すると、そのキーの値は `.po` にエントリがないため `missing` に数えられます。原文更新のフローでも、毎回同じ値を指定します。

キーパスの書き方は次のとおりです。

- 複数のキーパスは `,` で区切って指定します（例: `--front-matter-keys title,description`）。
- 入れ子のマッピングのキーは `.` で区切ってつなぎます（例: `seo.title` は `seo` の下の `title`）。
- キーパスの途中または末尾がシーケンス（YAML のリスト）に当たったときは、そのシーケンスのすべての要素が対象になります（例: `tags` ですべてのタグ、`authors.name` ですべての著者の `name`）。要素の番号で指定することはできません。
- `.` を含むキーは指定できません。

たとえば、次のフロントマターに `--front-matter-keys title,seo.description,tags` を指定すると、`title`、`seo` の下の `description`、`tags` の 2 つの要素が翻訳の対象になります。

```yaml
---
title: Getting started
seo:
  description: A short introduction.
tags:
  - tutorial
  - basics
---
```

キーパスに一致する値がない文書では、そのキーパスは無視されます（エラーにはなりません）。キーパスが空のセグメントを含む（`a..b`、`.a` など）ときは、エラーを表示して終了コード 1 で終了します。一致した値がマッピングのときは警告を表示し、その値は翻訳の対象にしません。対応している YAML の構文の範囲は [既知の制限](limitations.md) を参照してください。

## 翻訳ファイルの編集に使うツール

`monde` は `.pot` と `.po` を作り、マージし、`.po` から翻訳済みの Markdown を作りますが、`.po` の訳を編集する機能は持ちません。訳の入力、fuzzy の印を外す作業、未翻訳や fuzzy のエントリの絞り込みは、PO に対応した翻訳プラットフォームやエディタで行います。たとえば次のものがあります。

- デスクトップのエディタ: Poedit、Lokalize
- テキストエディタの拡張: Emacs の po-mode
- `.po` を読み書きできる Web の翻訳プラットフォーム

`monde` が作る `.pot` と `.po` は GNU gettext の形式に従い、`msgfmt --check` を通ります。翻訳者は、普段使っている PO 対応のツールでそのまま作業できます。

## 翻訳済み Markdown の差分レビュー

`translate` は、原文のうち翻訳する文字列の範囲だけを訳に置き換え、それ以外を原文のバイト列のまま残します。構文木から文書を作り直さないため、リストの記号（`-` か `*` か）、強調の記号（`*` か `_` か）、空行、インデント、改行コード（LF か CRLF か）、コードブロックの中身は原文と同じになります。

このため、翻訳済みの Markdown（`hello.ja.md`）を `.po` と一緒にリポジトリに置いておくと、バージョン管理の差分で翻訳をレビューできます。

1. 原文更新のフローで `update` と翻訳を行い、`translate` で翻訳済みの Markdown を作り直します。
2. `git diff hello.ja.md` で、前回の翻訳済みの Markdown との差分を確かめます。

書式は毎回原文から同じように引き継がれるため、差分は、原文の更新に合わせて訳を変えた箇所（と、原文で書式を変えた箇所）だけになります。訳し直していない段落や、書式だけの変更が差分に現れないので、レビューする人は変わった訳だけを確かめられます。同じように、`.po` の差分では、msgid と msgstr のどこが変わったかを確かめられます。

訳していない箇所は原文のまま出力されるため、差分に英語の文が残っていれば、訳し漏れ（未翻訳または fuzzy のエントリ）があることが分かります。
