# 既知の制限

この章では、初版の `monde` が対応していない記法や機能と、そのときの振る舞いをまとめます。ここに書いた振る舞いは不具合ではなく、初版の仕様です。多くは原文の書き方や運用で避けられます。

各サブコマンドの詳しい振る舞いは [コマンドリファレンス](commands.md) を、翻訳の手順は [翻訳フロー](workflow.md) を参照してください。

## Markdown: GFM の記法

初版が対応する Markdown は [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) です。GitHub Flavored Markdown（GFM）で拡張された次の記法には対応していません。これらは CommonMark としての解釈のまま、ふつうの段落やリスト項目の文字列として翻訳の対象（msgid）になります。

| 記法 | 初版での扱い |
| --- | --- |
| 表 | 表全体が 1 つの段落として扱われ、ヘッダ行、区切り行（`---` を並べた行）、各行を改行でつないだ 1 つの msgid になります。セル単位では翻訳できません。 |
| タスクリスト | 通常のリスト項目として扱われます。チェックボックスの記号（`[ ]`、`[x]`）は、項目の文字列の先頭に含まれたまま msgid になります。 |
| 取り消し線 | `~~` は記号ではなくただの文字として、前後の文字列とともに msgid に含まれます。 |
| 自動リンク（拡張） | `www.example.com` や `https://example.com` のように `<` と `>` で囲まない URL は、リンクではなくただの文字列として msgid に含まれます（`<https://example.com>` の形は CommonMark の自動リンクです）。 |
| 脚注 | 本文の参照（`[^1]`）は文字列の一部として msgid に含まれます。脚注の定義（`[^1]: ...` で始まる行）は、多くの場合ふつうの段落として 1 つの msgid になります（定義の内容が URL のような 1 語だけのときは CommonMark のリンク参照定義と解釈され、翻訳の対象になりません）。 |

GitHub などで表示するときは GFM として解釈されるため、訳文でもこれらの記号を原文と同じ位置に同じ形で書いてください。たとえば表の msgid を訳すときは、`|` の数と区切り行を変えずにセルの中の文字列だけを訳します。記号が崩れると、翻訳済みの Markdown が表やタスクリストとして表示されなくなります。

GFM の表（セル単位の翻訳）、タスクリスト、取り消し線、自動リンクには次の版で対応する予定です。脚注はさらに先の版で対応する予定です。

## YAML フロントマターの対応範囲

YAML フロントマターは、`--front-matter-keys` を指定したときだけ YAML として解析します。指定しないときは解析せず、フロントマター全体を原文のまま出力するため、この節の制限は関係しません。

`--front-matter-keys` を指定したとき、Monde が扱えるのは YAML の一部（ブロック形式とフロー形式のマッピングとシーケンス、プレーン・シングルクオート・ダブルクオートのスカラー、ブロックスカラー、コメント）です。次の構文には対応していません。

- アンカー（`&name`）
- エイリアス（`*name`）
- タグ（`!!str` など、`!` で始まる指示）
- ディレクティブ（`%YAML` など、`%` で始まる行）
- 複雑なキー（`? ` で始まるキー）
- 複数ドキュメント

アンカー、エイリアス、タグ、ディレクティブ、複雑なキーがフロントマターの中にあると、`extract` と `translate` はその位置の行番号と構文の種類を示すエラーを表示し、出力を書かずに終了コード 1 で終了します。エラーは次の形式です（`<kind>` は `anchor`、`alias`、`tag`、`directive`、`complex mapping key` のいずれか）。

```text
<path>:<line>: error: unsupported YAML syntax: <kind>
```

翻訳するキーの値でなくても、フロントマターのどこかにこれらの構文があればエラーになります。アンカーとエイリアスで値を共有している場合は、値をそれぞれのキーに書き下してください。

複数ドキュメントについては、フロントマターは 1 行目の `---` から、その後に最初に現れる `---` または `...` だけの行までです。そこで 1 つ目のドキュメントが終わり、2 つ目以降のドキュメントにあたる部分はフロントマターではなく本文の Markdown として扱われます。

## YAML フロントマターのその他の制限

### ルートが 1 つの文字列（スカラー）だけのフロントマター

フロントマター全体が `key: value` の形やリストではなく、1 つの文字列（スカラー）だけからなる場合、次の 2 つの書き方は YAML としては正しくても解析できず、エラーになります。

- プレーン（引用符なし）の文字列の 2 行目以降を、インデントなし（行頭から）で書いたもの
- `|` や `>` で始まるブロックスカラーの内容を、インデントなし（行頭から）で書いたもの

2 行目以降をインデントした文字列、ダブルクオートで囲んだ複数行の文字列、内容をインデントしたブロックスカラーは扱えます。次の例は、2 行目がインデントなしのためエラーになります。

```yaml
---
This front matter is a single string
that continues on the next line.
---
```

キーパスはマッピングのキーをたどるため、このようなフロントマターには `--front-matter-keys` で翻訳できる値がもともとありません。`--front-matter-keys` を指定しなければエラーにはなりません。`title: ...` のようなキーを持つふつうのフロントマターには、この制限は関係しません。

### フロー形式の継続行のインデント

`[` と `]`、`{` と `}` で囲むフロー形式のシーケンスやマッピングを複数の行に分けて書くとき、2 行目以降のインデントは検査しません。そのため、YAML の仕様ではインデントが足りずに誤りとなる書き方も、エラーにならずに受け付けます。

```yaml
---
tags: [tutorial,
basics]
---
```

このような書き方でも、翻訳済みの Markdown では訳した値以外が原文のまま出力され、フロントマターの書き方が変わることはありません。ただし、Jekyll や Hugo などほかのツールは、厳密な YAML として読めないフロントマターをエラーにすることがあります。ほかのツールでも読めるように、継続行はインデントしてください。

### ダブルクオートのキーの中の U+2028・U+2029

ダブルクオート（`"`）で囲んだ**キー**に、U+2028（LINE SEPARATOR）や U+2029（PARAGRAPH SEPARATOR）の文字がエスケープせずにそのまま含まれていると、YAML 1.1 に従うパーサ（Jekyll が使う Psych、古い版の Hugo、js-yaml の既定の設定など）は、そのキーを複数の行に分かれたものとみなして読めないことがあります。

Monde はこのようなフロントマターも読み込めます。また、Monde はキーを翻訳せず、キーは原文の UTF-8 のバイト列のまま出力します。そのため、原文が読めるツールでは翻訳済みの Markdown も読め、値の翻訳にも影響しません。原文の時点でほかのツールが読めない場合は、キーの中のこれらの文字を `\u2028`、`\u2029` とエスケープして書いてください。

なお、翻訳した**値**は Monde が YAML として正しく読める形に整えて出力するため、訳文にこれらの文字が含まれていても問題ありません。

## 処理の単位と設定

- **1 回の実行で 1 ファイル**: 各サブコマンドが 1 回の実行で扱える Markdown や `.pot` / `.po` は 1 つずつです。複数のファイルやディレクトリをまとめて処理することはできません。位置引数を余分に指定すると引数の誤り（終了コード 2）になります。複数の文書を翻訳するときは、文書ごとにコマンドを実行してください（シェルのループや Makefile などで繰り返します）。
- **設定ファイルはない**: Monde は設定ファイルや環境変数からオプションを読みません（`init` の言語コードを決めるときの `LC_ALL`、`LC_MESSAGES`、`LANG` を除く）。`--front-matter-keys` などのオプションは、実行のたびにコマンドラインで指定します。`extract` と `translate` には同じ `--front-matter-keys` を指定する必要があるため、スクリプトなどで値を 1 か所にまとめておくと安全です。
- **複数形のエントリは読み込めるだけ**: 複数形のエントリ（`msgid_plural` と `msgstr[0]`、`msgstr[1]` などを持つエントリ）を含む `.po` を読み込んでもエラーにはなりません。`update` では、テンプレートのエントリも複数形で `msgid_plural` が同じなら `msgstr[n]` をすべて引き継ぎます。単数形と複数形が食い違うときは、GNU gettext の `msgmerge` と同じく訳を移したうえで fuzzy にします（複数形から単数形になったエントリには `msgstr[0]` だけが残ります）。ただし、本格的な対応はしていません。Markdown から取り出す文字列はすべて単数形のエントリになり、Monde が複数形のエントリを作ることはありません。`Plural-Forms` に従った形の選び分けや、`msgstr[n]` の個数の検査もしません。
- **翻訳率による出力の制御はない**: `translate` は、翻訳率がいくつであっても翻訳済みの Markdown を出力し、終了コード 0 で終了します（訳のない箇所は原文のまま）。翻訳率が一定に満たないときに出力しない、またはエラーにするといったオプションはありません。必要なときは、標準エラー出力の統計（`translate: ... P.Q% translated`）を読んで判断してください。

## 構造を変え得る訳文の警告

`translate` は、訳文を原文の該当する範囲にそのまま差し込みます。訳文に Markdown のブロックを作る内容が含まれていると、翻訳済みの Markdown の構造（段落の数、見出し、リストなど）が原文と変わってしまいます。Monde はこのような訳文をエスケープしたり取り除いたりはせず、警告を表示したうえで訳文をそのまま使って出力を書き、終了コード 0 で終了します。警告は `-q` を指定しても表示されます。

警告になるのは次の 3 つの場合で、それぞれ次の形式で表示されます（`<path>` は原文の Markdown のパス、`<line>` は原文で該当する文字列が始まる行、`<n>` は訳文の中の何行目かを表す番号です）。

| 場合 | 警告の形式 |
| --- | --- |
| 訳文に空行（空白やタブだけの行を含む）がある | `<path>:<line>: warning: translation contains a blank line (msgid at line <line>)` |
| 訳文のいずれかの行が、ブロックを始め得る記号（`#`、`>`、リストの記号 `-` `+` `*` や `1.`、コードフェンス、区切り線、setext の下線 `=` など）で始まる | `<path>:<line>: warning: translation line <n> starts with a block marker (msgid at line <line>)` |
| 1 行の見出しの訳文に改行がある | `<path>:<line>: warning: translation of a one-line heading contains a line break (msgid at line <line>)` |

たとえば、`hello.md` の 5 行目の段落の訳文が `- ` で始まっていると、次の警告が表示されます。

```text
hello.md:5: warning: translation line 1 starts with a block marker (msgid at line 5)
```

YAML フロントマターの値の訳文は、Monde が YAML として正しい形（必要ならダブルクオートで囲むなど）に整えて出力するため、この警告の対象になりません。

### 警告が出たときの対処

警告が出たら、`<line>` が示す原文の行の文字列に対応する `.po` のエントリを開き、訳文を見直してください。

- 訳文の空行を取り除きます。原文の 1 つの段落は、訳文でも 1 つの段落にします。段落を分けたいときは、原文の段落を分けてから `extract` と `update` をやり直します。
- 訳文の行頭がブロックの記号にならないようにします。文の途中で改行した結果、行頭に `-` や `#`、`1.` などが来た場合は、改行の位置を変えます。記号を文字として行頭に置く必要があるときは、`\-`、`\#` のようにバックスラッシュでエスケープします。
- 1 行の見出しの訳文は、改行を含まない 1 行にします。

直した後に `translate` をもう一度実行し、警告が出ないことと、翻訳済みの Markdown の差分（[翻訳済み Markdown の差分レビュー](workflow.md#翻訳済み-markdown-の差分レビュー) を参照）で構造が原文と同じであることを確かめてください。
