## Implementation Notes
- 1.2: `mnd_md_unicode_is_space` は Zs だけを判定する。CommonMark の Unicode whitespace（タブ、LF、FF、CR を含む）は、使う側（Delims、LinkRef）でこの 4 文字を別に判定する。`mnd_md_unicode_fold` の出力は NUL 終端しない（最大 `MND_MD_UNICODE_FOLD_MAX` バイト）。
- 1.3: `mnd_md_entity_lookup(name, len, &utf8, &utf8_len)` の名前は `&` と `;` を含まない（呼び出し側が `;` が続くことを確かめる）。名前の最大長は `MND_MD_ENTITY_NAME_MAX`（31）。
- 1.4: spec_reader の API は `mnd_md_spec_load(path, &spec, diags)` / `mnd_md_spec_free`。例は `spec.examples[i]` の `number`、`section`、`markdown`、`html`（`mnd_buf_t`、NUL 終端）。
- 2.1: 共有の内部 API（`md_internal.h`）: アリーナ `mnd_md_arena_*`（ゼロ初期化）、作業用の配列 `mnd_md_array_*`（伸長は確保＋複製＋解放）、`mnd_md_size_mul`、`mnd_md_doc_create`、`mnd_md_node_new/append_child/insert_before/insert_after/unlink`。テスト用の確保関数は `tests/markdown/test_alloc.h` の `mnd_md_test_alloc_t`（n 回目で失敗、0 は失敗しない）。
- 2.2: 行の分割は `mnd_md_lines_next(data, &pos, end, &line)`（`mnd_md_phys_line_t`、`pos >= end` で false）。行番号の表は `mnd_md_line_index_build(&index, data, len, arena)` でアリーナに作り、`mnd_md_line_index_line_of` で引く。
- 2.3: Scan の判定関数は、インデントを除いた位置（最初の空白でない文字）から呼ぶ。インデント 3 以下の検査、判定の優先順位、段落の中断の条件（空の項目、開始番号 1）は呼び出し側（BlockParser）が行う。`mnd_md_scan_pos_t.column` は取り除いた仮想の空白を含む論理的な桁で、物理的な桁は `column + pad`。空の ATX 見出しと情報文字列のないフェンスの範囲は、記号の並びの直後の空の範囲。
- 2.4: Html の字句の関数は `(data, pos, end)` の連続したバイト列だけを見て、コンテナのプレフィックスを知らない。InlineParser（4.1）は、プレフィックスをまたぐ生の HTML を論理的な文字列か連続した範囲で扱う。閉じのない `<!--`・`<?`・CDATA・引用符の属性値は `end` まで走査するため、InlineParser は「この位置より後ろにない」ことを記録して二乗の時間を避ける（8.3）。条件 6・7 の終わり（空行）は BlockParser が判定する。`<pre/>` は spec の文言どおり種類 0。
- 2.5: `mnd_md_logical_text` は、内容が空でない行を 1 バイト以上重なるときだけ含め、内容が空の行は `start <= content.start <= end` で含める（リーフの範囲を渡すと最後の空行が残る）。pad は `start <= content.start` のときだけ補う。`mnd_buf` は malloc を直接使うため、Text のメモリ不足はテストできない。
- 2.6: 範囲の検査は `mnd_md_tree_check(doc, &result)`（`result` は NULL 可）と、失敗時に NAOS_NOTE を出す `mnd_md_tree_check_note(doc)`（`tests/markdown/tree_check.h`）。`eol_len` は物理的な行の行末記号と一致すること、根は DOCUMENT で範囲の終わりが len であることも検査する。
- 2.7: HTML の正規化は `mnd_md_html_normalize(html, len, &out)`（`tests/markdown/html_normalize.h`）。Python 3.13 の HTMLParser の流れを移植したもので、実体名は HTML5 の表で文字に戻す（normalize.py との設計どおりの違い）。
- 3.1: 解析の作業状態は `md_internal.h` の `mnd_md_parser_t`（開いているブロックの配列 `open`、リーフの行の作業用配列 `leaf_lines`）。ブロックの段階は `mnd_md_block_run`、`match_open_blocks` は種類ごとの switch で、3.2・3.3・5.1 はそこに case を足す。`mnd_md_parse` は `mnd_md_block_run` の false を一律にメモリ不足として扱うため、5.1 で方言の規則の失敗を加えるときは別の経路が要る。行番号は `mnd_md_parser_line_of`、ノードの行番号は `mnd_md_parser_set_node_lines`。
- 3.2: リストを分けるのは記号の種類（箇条書きの文字、順序付きの区切り文字）の違いだけで、開始番号では分けない（CommonMark どおり。タスクの文言の「開始番号」は段落の中断の条件にだけ効く）。`item.content_indent` は直近の親のコンテナの照合が終わった桁からの相対値（cmark と同じ）。遅延継続行のプレフィックスは、照合できたコンテナのバイトと行の先頭の空白からなる。段落は行の先頭の空白をすべて除くため pad は 0 になり、pad が 0 以外になるのはコードブロックの行（3.3）。3.3 のリーフの開始は `try_block_starts` と `record_blank_line` のコメントの位置に足し、`can_contain` と `is_leaf` に新しい種類を加える。
- 3.3: ブロックの開始の順序は `try_block_starts`（インデントコード、方言の規則の位置（5.1）、引用、ATX、フェンス、HTML 1〜7、Setext、テーマ区切り、リスト項目）。Setext に変える前に `paragraph_take_definitions(parser, &remains)` を呼ぶ受け口があり、3.4 が中身を入れる（段落を取り除くときは `try_block_starts` の `*matched` の調整を確かめる）。閉じフェンスのないフェンスコードの範囲は最後の行（空行でもよい）の `line_end` まで。HTML ブロックの範囲はコンテナのプレフィックスの直後（先頭の空白を含む）から。
- 3.4: 定義の表は `struct mnd_md_doc` の `refs`（オープンアドレス法、スロットは文書のアリーナ）。インラインの段階（4.3）では、ラベルの論理的な文字列を `mnd_md_linkref_normalize` で要素の大きさ 1 の `mnd_md_array_t` に正規化し、`mnd_md_linkref_lookup(doc, items, count)` で引く。ラベルの上限 `MND_MD_LINKREF_LABEL_MAX`（999）は符号位置で数える。正規化はアンエスケープしない。タイトルのない定義の `title` は `dest.end` の空の範囲で `title_delim` は 0。定義だけの段落が `---` の行で取り除かれると、テーマ区切りになる（commonmark.js と同じ）。
