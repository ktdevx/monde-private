# Implementation Plan

> **進め方の前提**: 設計の Migration Strategy の 5 段階（移動 → 自己完結 → 改名 → 独立ビルドとパッケージ → CI と文書）の順に進める。引数パーサは 1 つの静的ライブラリなので、公開インターフェースを変えるタスク（2.2、3.1）の直後は、利用側（CLOpts のテスト、Monde 本体）がビルドできない。その状態は、同じ大タスクの中の後続のタスクで解消する。各大タスクの終わりでは、Monde の構成・ビルド・CTest の全件が成功する。
>
> **履歴の保持**: タスク 1.1 のコミットには、移動と最小限の修正だけを入れる。内容の書き換えは 2 以降のコミットに分ける。

## Implementation Notes
- 1.1: 基準のコミットは 09516df、`ctest -N -L cli_args` は 307 件、全件は 1494 件。基準の `monde` と配布物のファイルの一覧はコミット b4a73d8 のメッセージに記録した
- 2.1: エラーの列のスイート `errors_api`（8 件）と内部バッファのスイート `buf`（4 件）を加え、`-L clopts` は 319 件になった。タスク 2.3 の件数の基準はこの 319 件
- 2.2: 整形の関数は `mnd_args_format_*` が確保した文字列を返し、解放は `mnd_args_text_free`（3.1 の改名で `clopts_text_free`）。Windows の UTF-16 変換は Linux では実際にはコンパイルしていないので、Windows の CI で確かめる
