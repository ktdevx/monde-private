# Implementation Plan

- [x] 1. foundation への文字コード変換の部品の追加
- [x] 1.1 UTF-8 と UTF-16 を相互に変換する Windows 専用の部品を追加し、単体テストを書く
  - NUL 終端の UTF-8 を、確保した UTF-16 に変換する機能と、その逆の機能を用意する。結果は呼び出し側が解放する
  - 不正な UTF-8 や対になっていないサロゲートは置換文字にせず失敗とし、理由を `invalid UTF-8`・`invalid UTF-16`・`out of memory` の固定の文字列で返す。診断は追加しない
  - 長さが変換 API の扱える範囲を超えないことを確認してから変換する
  - Windows でだけソースをビルドに加え、テストファイルとスイート `wide` も Windows でだけ foundation のテストに加える（他の OS では空の翻訳単位を作らない）
  - steering の予約済みの短縮名に、本 spec が使う `wide`（foundation）と `args`（cli_args）を追記する
  - 完了時: Windows の CI で wide スイートの「日本」の相互変換、サロゲートペアの往復、空文字列、`C0 80` が `invalid UTF-8`、`0xD800` 単独が `invalid UTF-16` になるテストが合格し、Linux と macOS ではビルドとテストが従来どおり通る
  - _Requirements: 10.2, 10.3_

- [x] 1.2 ファイル入出力の既存の変換を、新しい部品に置き換える
  - ファイル入出力が内部に持っていた UTF-8 から UTF-16 への変換を削除し、1.1 の部品を使う
  - 部品から返る理由を、既存のメッセージ（`file path is not valid UTF-8`、`out of memory`）に対応付け、公開 API と挙動を変えない
  - 完了時: foundation の既存のテスト（非 ASCII のディレクトリとファイル名での読み書きを含む）が変更なしで 5 環境すべてで合格する
  - _Requirements: 10.2_

- [x] 2. cli_args モジュールとテストの雛形
- [x] 2.1 cli_args モジュールとテスト実行ファイルを作り、構成・ビルド・テストの手順を通す
  - 設計の型（宣言、状態、結果、引数列）と関数の宣言を持つ公開ヘッダ 3 つと内部ヘッダを置き、設計で定めた 5 つのソース（宣言の検査、結果の保持、走査、文面、引数の取得）を最初から登録する。各ソースは空の翻訳単位にならず、警告なしでコンパイルできるようにする
  - モジュールは foundation に依存し、Windows でだけ shell32 をリンクする。`src/` と `tests/` のビルドファイルにモジュールを追加する
  - テスト実行ファイルを、9 スイート（decl、dispatch、long、short、values、positional、errors、help、argv）を登録するエントリポイントと、スイートごとに 1 つのテストファイルで作り、各スイートに雛形のテストを 1 件置く
  - 架空のプログラム `tool`（バージョン `1.2.3`、サブコマンド `build`・`copy`・`cat`）のテスト用の宣言を、設計の Testing Strategy のとおりに定義する。Monde 固有の名前を使わない
  - ソースとテストファイルの登録はここで完了させ、以降のタスクは自分の担当のソースとテストファイルだけを編集すれば済むようにする
  - 完了時: 標準の 3 行の手順が 5 環境で成功し、CTest に `cli_args_tests.<suite>.<test>` 形式のテストが 9 スイート分表示され、`ctest -L cli_args` で実行できる。`BUILD_TESTING=OFF` でも `monde_cli_args` がビルドできる
  - _Requirements: 1.1, 1.2, 1.3, 11.1, 11.2_

- [ ] 3. 宣言の検査と引数の取得
- [x] 3.1 (P) 宣言の妥当性の検査と、名前による検索を実装し、単体テストを書く
  - 設計の DeclCheck の表の規則（名前の空・予約名・重複、短い名前の文字、フラグの必須・既定値、必須と既定値の両立、リスト値の既定値の空の項目、位置引数の範囲と名前の数）をすべて検査し、誤りごとに `invalid argument declaration: ` で始まる診断を追加する
  - サブコマンド、長い名前、短い名前の検索をバイト単位の完全一致で行い、値の表示名の既定（`VALUE`）と、位置引数の添字から名前を求める規則（上限なしでは最後の名前を繰り返す）を用意する
  - 雛形のテストを本物のテストに置き換える
  - 完了時: decl スイートで、各規則の違反が名前を含む診断になること、誤りを 2 つ含む宣言で診断が 2 件になること、`tool` の宣言が検査を通ること、大文字と小文字の違う名前が見つからないことのテストが合格する
  - _Boundary: DeclCheck_
  - _Requirements: 1.4, 1.5, 1.6, 2.4, 3.7_

- [ ] 3.2 (P) コマンドライン引数を UTF-8 の列として取得する機能を実装し、単体テストを書く
  - Windows 以外では、渡された引数列をコピーも変換もせずに返し、所有しない印を付ける
  - Windows では、プロセスのコマンドラインを取得して要素に分割し、1.1 の部品で各要素を UTF-8 に変換して所有する。変換できない要素があれば、その添字（0 起点）を示す診断を追加し、確保済みの領域を解放して失敗を返す
  - 取得結果の解放は、初期状態や解放済みに対しても安全にする
  - 雛形のテストを本物のテストに置き換える
  - 完了時: argv スイートで、Windows 以外では渡した配列がそのまま返ること、Windows では UTF-16 の「日本」が UTF-8 のバイト列になること、2 番目の要素に `0xD800` を含むと失敗して添字 `1` を含む診断が返ること、実際のコマンドラインから 1 個以上の要素が得られることのテストが合格する
  - _Boundary: ArgvSource_
  - _Depends: 1.1_
  - _Requirements: 10.2, 10.3, 10.4_

- [ ] 4. 解析結果の保持と文面の生成
- [ ] 4.1 (P) 解析結果の保持と取得を実装し、単体テストを書く
  - 選択されたサブコマンドのオプションと同じ並びで値を保持し、フラグの指定、単一の値の後勝ち、リスト値のカンマ区切りと連結（項目の空白はそのまま）、位置引数の記録を行う
  - リスト値に空の項目があれば何も追加せずに使い方のエラーを返し、確保の失敗はメモリ不足として返す
  - 明示的に指定されていないオプションに既定値を適用し、明示的な指定かどうかを区別できるようにする
  - 単一の値と位置引数は引数列や宣言の文字列を指し、リスト値の項目だけをコピーする。引数列を書き換えない
  - 長い名前による取得関数（指定の有無、フラグ、値、リストの件数と項目、位置引数）を用意し、宣言されていない名前には偽・NULL・0 を返す。結果の解放は繰り返し呼んでも安全にする
  - 雛形のテストを、内部の書き込み関数を直接使う values スイートのテストに置き換える
  - 完了時: values スイートで、`a,b` と ` a , b` の項目、空の項目の拒否、2 回の追加の連結、単一の値の後勝ち、既定値の適用と明示的な指定の区別、未宣言の名前の扱いのテストが合格する
  - _Boundary: ResultStore_
  - _Depends: 3.1_
  - _Requirements: 5.1, 5.3, 5.4, 5.5, 5.6, 6.1, 10.1, 10.5_

- [ ] 4.2 (P) ヘルプ、バージョン、使い方の案内の文面の生成を実装し、単体テストを書く

  - 位置引数の使い方の書き方（必須、省略可、上限なし）、オプションの左列（短い名前の有無、値とリスト値の表示）、必須と既定値の注記を設計どおりに出す
  - 段落ごとに左列の最大幅を求めて説明の開始位置を揃え、末尾に空白を出さず、改行を LF だけにする
  - バージョンの 1 行と、サブコマンドの有無に応じた使い方の案内の 1 行を生成する
  - 雛形のテストを本物のテストに置き換える
  - 完了時: help スイートで、`tool` の全体のヘルプ、`build`・`copy`・`cat` のヘルプ、バージョン、案内 2 種が期待する文面のリテラルとバイト単位で一致し、同じ宣言から 2 回生成した文面が一致するテストが合格する
  - _Boundary: HelpFormatter_

- [ ] 5.4 位置引数、終端、事後の検査、誤りの優先順位を実装する
