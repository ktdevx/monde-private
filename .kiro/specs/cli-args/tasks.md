# Implementation Plan

> この計画は、`--no-<name>` 形式の否定への対応（2026-11-11 の改訂、要件 14 と 1.5、11.1 の変更）のためのものである。それより前の計画（サブコマンドのない形式への対応など。すべて完了済み）は、このファイルの履歴に残っている。
>
> **進め方の前提**: 設計は design.md の「改訂（2026-11-11）: 否定できるフラグ」の節に従う。作業の対象は `cli_args/` の中だけで、`src/`、`tests/`、`docs/`、ルートの README は変更しない。確認は `ctest -L clopts` で行い、最後に全体と CLOpts の単独構成で確かめる。

- [ ] 1. 基盤: 否定できるフラグの宣言と結果の形
- [x] 1.1 宣言に「否定できる」「既定で有効」を、結果に「有効かどうか」を持たせ、フラグの記録を有効・無効を受け取る形にする
  - 宣言の型の末尾に、否定の形を受け付けるかどうかと、既定で有効かどうかを足す。書かなければ「否定できない」「既定で無効」になる
  - 結果の値の末尾に、フラグが有効かどうかを足し、初期値を無効にする
  - フラグの記録を「明示的に指定された」と「有効か無効か」を同時に書く形にし、肯定の形（長い名前、短い名前、まとめ書き）の記録が有効を渡すようにする
  - フラグの取得が「有効かどうか」を返し、明示的な指定の取得は今までどおり「指定されたかどうか」を返すようにする
  - 完了時: `ctest -L clopts` で、既存のスイートがテストのソースと期待値を変えずにすべて合格する
  - _Requirements: 1.5, 14.1, 14.5, 14.6, 14.13, 14.14_
- [x] 1.2 テスト用の架空のプログラム `neg` と、スイート negate を加える
  - 設計書の Testing Strategy のとおりに `neg` を宣言する（ルートに `color`、`pager`、`no-cache`、`wrap`、`name`、子コマンド `run` に `force`、`sync`、`quiet` と位置引数 `FILE`）。Monde 固有の名前を使わない
  - スイート negate をテストの実行ファイルに登録し、最初のテストとして、否定できるフラグの肯定の形と未指定の 2 つの状態（`neg --color run`、`neg run` での `color`）を確かめる
  - 完了時: `ctest -L clopts` にスイート negate のテストが現れて合格し、`neg` の宣言が宣言の検査を通る
  - _Requirements: 11.1, 14.1, 14.5, 14.6_

- [ ] 2. 中核: 宣言の検査、ヘルプ、否定の形の解析、既定の適用
- [x] 2.1 否定に関する宣言の誤りを検出する
  - フラグではないオプションを否定できると宣言したら、そのオプションと経路を示す宣言の誤りにする
  - 否定できるフラグではないオプション（否定できないフラグ、単一の値、リスト値）を既定で有効と宣言したら、宣言の誤りにする。フラグに文字列の既定値を付けた宣言が、今までどおりの誤りになることも確かめる
  - 否定できるフラグ `<name>` と長い名前 `no-<name>` のオプションが、同じコマンドの中、または祖先と子孫の間（どちらの向きでも、祖先の側が引き継がないオプションでも）にあれば、設計書の文面の宣言の誤りにする
  - 否定できない `color` と `no-color` が並ぶ宣言、`no-x` という名前の否定できるフラグだけの宣言は、妥当とする
  - 完了時: decl のスイートに上の各場合のテストがあり、誤りの文面が設計書の「メッセージ」の表と一致して合格する。既存の decl のテストは期待値を変えずに合格する
  - _Boundary: DeclCheck_
  - _Requirements: 14.10, 14.11, 14.16_
- [x] 2.2 (P) ヘルプで、否定できるフラグを `--[no-]<name>` と表し、既定で有効を注記する
  - 否定できるフラグの左列で、長い名前の前に `[no-]` を挟む。左列の幅の計算にも同じ分を足し、説明の開始位置が最大幅に揃うようにする
  - 既定で有効のフラグの説明に ` (default: on)` を、値付きオプションの既定値の注記と同じ位置と空白の規則で付ける。既定で無効のフラグには付けない
  - `neg` のルートコマンドと `run` のヘルプを、期待する文面のリテラルとバイト単位で比較する。`run` のヘルプに、引き継いだ `--[no-]color` と `--[no-]pager` が現れることを含む
  - 完了時: negate のスイートのヘルプのテストが合格し、help、single、nested、inherit のスイートの既存のヘルプの期待値が 1 バイトも変わらずに合格する
  - _Boundary: HelpFormatter_
  - _Depends: 1.2_
  - _Requirements: 9.5, 11.4, 14.12, 14.13, 14.17_
- [x] 2.3 `--no-<name>` を否定の形として解析し、後に書いた指定を優先する
  - 有効なオプションの検索に、否定の形の検索（`no-` を外した名前が否定できるフラグと一致するか）を加える。引き継ぎの範囲は、肯定の形の検索と同じにする
  - 長い名前の照合で、完全一致が見つからなかったときに限り、否定の形の検索を行い、見つかればそのフラグを無効として記録する。`no-cache` のように `no-` で始まる名前のオプションは、今までどおり完全一致で扱う
  - 肯定の形と否定の形を混ぜて繰り返しても誤りにせず、引数列で最後の指定を残す。引き継ぐフラグを子コマンド名の前後にまたがって指定した場合も同じにする
  - 否定の形に `=` で値を付けたら、利用者が書いた形（`--no-<name>`）を示す「値を取らない」の誤りにする
  - 否定できないフラグ、値付きオプション、リスト値、まだ選択されていない子コマンドのフラグ、存在しない名前、`--no-` だけ、前方一致、大文字と小文字の違いへの `--no-<name>` は、その引数を示す未知のオプションの誤りにする
  - `--` の後の `--no-<name>` が位置引数になること、末端コマンドで未知の `--no-<x>` の後ろに `--help` があればヘルプを優先することを確かめる
  - 完了時: negate のスイートに、設計書の Testing Strategy の「肯定・否定・未指定」「後に書いた指定の優先」「引き継ぐフラグ」「完全一致の優先」「値の指定」「未知のオプション」「ほかの規則との組み合わせ」の各テストがあり、合格する
  - _Boundary: Parser, DeclCheck_
  - _Depends: 1.2_
  - _Requirements: 3.6, 3.7, 6.3, 8.3, 14.2, 14.3, 14.4, 14.7, 14.8, 14.9_
- [x] 2.4 既定で有効のフラグを、指定がないときに有効として返す
  - 走査が成功した後の既定値の適用で、明示的に指定されていない既定で有効のフラグを有効にする。明示的な指定の取得は偽のままにする
  - 経路上のすべての段に適用し、引き継ぐフラグが子孫のコマンドでも既定の状態になるようにする
  - 明示的な指定（肯定の形、否定の形、その繰り返し）が既定より優先されることを確かめる
  - 完了時: negate のスイートで、`neg run` の `sync` と `pager` が「有効・明示的な指定なし」、`neg run --no-sync`、`neg --no-pager run`、`neg run --no-pager` が「無効・明示的な指定あり」、`neg run --no-sync --sync` が「有効・明示的な指定あり」になるテストが合格する
  - _Requirements: 12.6, 14.4, 14.15_

- [x] 3. CLOpts のバージョンを 0.2.0 に上げ、README に否定できるフラグを反映する
  - 公開の型の変更を表すため、CLOpts のプロジェクトのバージョンを 0.2.0 にする。Monde のバージョンは変えない
  - README の機能の一覧と宣言の説明に、否定できるフラグ（`--no-<name>`、既定で有効、ヘルプでの表記、取得の方法）を加える
  - 完了時: CLOpts の単独構成で、インストール後の利用の検証（`find_package` でバージョン 0.2.0 を要求する C と C++ の利用例）が合格する
  - _Requirements: 14.1, 14.14_

  - Monde の構成ですべてのターゲットをビルドし、`ctest` の全体（`cli`、`docs`、`clopts` を含む）を実行する。`ctest -L docs` が合格し、`monde` のヘルプの文面が変わっていないことを確かめる

  - `cli_args/` の製品コードとテスト用の宣言に、Monde 固有の名前が現れないことを確かめる

## Implementation Notes
- CI（MSVC）: `f(g(&x), x)` の形は引数の評価順が規定されず、MSVC では `x` が先に評価される。`&x` で値を設定する呼び出しは、別の文で先に済ませる。（前の計画から引き継いだ注意）
- 1.1: フラグの記録は `clopts_result_record_flag(result, ref, enabled)` に置いた。`cli_args/tests/values_test.c` が 2 引数の `clopts_result_set_flag` を呼ぶため、設計書の「`set_flag` に引数を足す」ではなく、`set_flag` を有効を渡すラッパとして残した。否定の形の記録（2.3）は `clopts_result_record_flag(..., false)` を使う。
- 1.2: `neg` の説明は設計書に `sync` の分しかないため、ほかは仮の文面を付け、`pager` は説明なしにした（2.2 のヘルプの期待値はこの宣言に従う）。`neg` の宣言の検査のテストは negate_test.c に置いた。
- 2.1: 宣言の検査に `clopts_find_negated` は要らなかったため、まだ加えていない。2.3（Parser）で加える。
