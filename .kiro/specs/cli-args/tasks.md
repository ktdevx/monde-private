# Implementation Plan

> この計画は、サブコマンドのない形式への対応（2026-11-10 の改訂）のためのものである。改訂前の実装の計画（すべて完了済み）は、このファイルの履歴に残っている。
>
> **進め方の前提**: `cli_args` は 1 つの静的ライブラリなので、宣言の型を変えると `monde` 本体と monde-cli のテストはビルドできなくなる。タスク 1.1 はライブラリのターゲットだけ、タスク 1.2 から 2.5 まではターゲット `cli_args_tests` だけをビルドして `ctest -L cli_args` で確認する。タスク 3.1 で全体のビルドが戻る。

- [ ] 1. 基盤: 新しい宣言と結果の形への載せ替え
- [x] 1.1 宣言の型と結果の保持を新しい形に置き換え、モジュールの製品コードを新しい型の上に載せ替える
  - プログラムがルートコマンドを指し、コマンドが子コマンドの配列を持ち、オプションが「子孫に引き継ぐ」の属性を持つ形に、宣言の型を置き換える。どのメンバーも 0 が「なし」を表すようにする
  - 解析結果を、経路の段ごとに値を持つ形に置き換える。選択されたコマンド、段の数、各段のコマンドを取得できるようにし、名前による値の取得は経路上のすべてのコマンドのオプションを対象にする。既定値の適用も経路上のすべての段を対象にする
  - 子コマンドの検索と、有効なオプション（選択中のコマンドのオプションと、祖先の引き継ぐオプション）の検索・列挙を用意する
  - ヘルプと案内の生成を、解析結果を受け取る形に変え、経路の文字列を生成する機能を加える
  - 走査、宣言の検査、ヘルプの書式は、この時点では挙動を変えない（入口の振り分け、`help` の語、回復走査、2 つのヘルプの書式、宣言の誤りの文面を残したまま、新しい型と段の上に載せ替える）。ただし宣言の検査は、既存の規則をルートコマンド自身にも適用し、子コマンドを持たないルートコマンド（オプションと位置引数を持つ）を妥当な宣言として受け付ける
  - これは型・結果の保持・検査・走査・文面にまたがる、明示的な載せ替えのタスクである
  - 完了時: ライブラリのターゲット `monde_cli_args` が、警告なしでビルドできる（テストはこの時点ではビルドできない）
  - _Boundary: 型, ResultStore, DeclCheck, Parser, HelpFormatter_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.8, 5.7, 10.1, 10.5_

- [ ] 1.2 テスト用の宣言と既存のスイートを新しい型に合わせ、1 段の構成の挙動が変わっていないことを確認する
  - テスト用の宣言 `tool` を、ルートコマンドの子コマンドとして指示付き初期化子で書き直す
  - 既存のスイートを、新しい型、取得関数、解析結果を受け取るヘルプと案内の生成に合わせる。decl スイートの書き換え可能な宣言には、ルートコマンドを加える
  - 期待する状態、値、メッセージ、文面は変えない
  - 完了時: `cli_args_tests` がビルドでき、既存のスイート（decl、dispatch、long、short、values、positional、errors、help、argv）が、期待値を変えずに `ctest -L cli_args` で合格する
  - _Boundary: CliArgsTests_
  - _Requirements: 2.8, 5.7, 10.1, 10.5, 11.3_

- [ ] 2. 中核: コマンドの木の上の検査、走査、文面
- [ ] 2.1 (P) 宣言の検査をコマンドの木に対応させる
  - ルートコマンドから木を深さ優先でたどり、既存の規則（名前、予約名、フラグの必須と既定値、リストの既定値、位置引数の範囲）をすべてのコマンドに適用する。深さに上限を設けない
  - 新しい規則を加える: ルートコマンドがない、子を持つコマンドの位置引数、同じ親の子コマンド名の重複、`help` という子コマンド名、祖先のオプションとの長い名前・短い名前の重複（引き継ぐかどうかによらない）、`version` という長い名前、自分自身を子孫に持つコマンド
  - 宣言の誤りのメッセージで、コマンドを経路の文字列（例: `nest remote`）で示す。既存の文面もこの形に変わるので（`in command 'run'` は `in command 'tool run'` に、子コマンド名の誤りには `in command '<path>'` が付く）、decl スイートの既存の期待値を新しい文面に直す
  - 入れ子の宣言は decl スイートの中の書き換え可能な宣言として持ち、共有のテスト用の宣言には触れない（2.2 と並行して進められるようにするため）
  - 完了時: decl スイートで、新しい規則の違反がそれぞれ名前を含む診断になること、既存の規則の違反が経路を含む新しい文面の診断になること、2 段目のコマンドの誤りが経路を示すこと、誤りを 2 つ含む宣言で診断が 2 件になること、自分自身を子に持つ宣言で検査が終わることのテストが合格する
  - _Boundary: DeclCheck_
  - _Requirements: 1.6, 1.7, 1.8, 1.9, 1.10, 2.7, 3.7_

- [ ] 2.2 (P) 入口の振り分けをなくし、ルートコマンドから始まる 1 つの走査に統合する
  - ルートコマンドを最初から選択し、トークンを左から順に、選択中のコマンドの宣言で解析する。`--help`、`-h`、子コマンドの選択、位置引数を、すべて同じ走査の中で扱う
  - 子を持つコマンドでは、オプションでない最初の引数を子コマンド名として解釈し、一致しなければ未知のサブコマンドとする。子コマンドの選択前にも、有効なオプションを解析する。`--` の後に引数があれば余分な引数の誤りとし、引数列が終われば子コマンドの未指定の状態を返す
  - 末端コマンドのルートでは、どの引数もサブコマンド名として解釈せず（`help` を含む）、引数なしの実行を通常の解析として扱う
  - `--version` を、ルートコマンドが選択中の間だけ、位置によらずバージョンの要求とする。子コマンドの選択後は未知のオプションとする
  - 使い方のエラーの接頭辞を、誤りを検出した時点の経路から作る
  - オプションの形の規則を、子コマンドの選択前にも同じように適用する: `--help=<x>` と、ルートコマンドでの `--version=<x>` は「値を取らない」の誤り、未知の長いオプションは `=` より前だけを示し、ASCII 以外のバイトを含む短いオプションは未知のオプションとする
  - `help` の語と回復走査は、このタスクでは改訂前の挙動のまま統合後の走査に移す（ルートコマンドの直後の `help` と、それに続く 1 語まで。回復走査は子コマンドの選択後の誤りだけ）。任意の深さへの対応と、それに伴う期待値の変更は 2.4 が行う
  - サブコマンドのないテスト用の宣言 `single` を加え、スイート single を新設する（解析に関する部分）。dispatch スイートを新しい規則に合わせる
  - 完了時: dispatch スイートで `tool`、`tool --`、`tool -- build`、`tool --help build`、`tool --version x`、`tool build --version` が設計どおりの状態と経路になり、single スイートで `single`（位置引数 0 個で成功）、`single help`（位置引数）、`single a -v b` と `single -v a b` の一致、`single --version x`、`single --bad` の接頭辞のテストが合格する。`tool --foo=bar` が `unknown option '--foo'`、`tool --help=1` と `tool --version=1` が「値を取らない」の誤りになる。`help` の語に関する dispatch スイートの既存のテストと、long、short、values、positional、errors の既存のテストが、期待値を変えずに合格する
  - _Boundary: Parser, CliArgsTests_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 7.2, 7.5, 7.6, 8.1, 8.2, 8.7, 8.8, 8.9, 11.2_

- [ ] 2.3 入れ子の構成と、子孫に引き継ぐオプションを検証し、必須の検査を経路全体に広げる
  - 入れ子のテスト用の宣言 `nest`（引き継ぐオプション、引き継がないオプション、必須の引き継ぐオプション、既定値を持つ引き継ぐオプションを含む）を加え、スイート nested と inherit を新設する
  - 必須のオプションの検査を、末端コマンドが選択されたときに、経路上のすべての段を対象にする（段 0 から順に、各段では宣言の順）
  - 引き継ぐオプションの値を、宣言した段に記録する。子コマンド名の前後で指定した場合に、同じオプションの繰り返しとして扱われることを確認する
  - 完了時: nested スイートで、`nest remote add n u -t x` の経路が 3 段になること、`nest remote bogus` と `nest remote add n` の診断が `nest remote: ` と `nest remote add: ` で始まること、`nest status` が成功することのテストが合格する。inherit スイートで、引き継ぐフラグを 3 つの位置のどこで指定しても同じ結果になること、引き継がないオプションが子コマンドの選択後に未知のオプションになること、単一の値の後勝ちとリスト値の連結、必須の引き継ぐオプションの充足と欠落、既定値、`nest status --tags a` が未知のオプションになることのテストが合格する
  - _Boundary: Parser, ResultStore, CliArgsTests_
  - _Requirements: 2.2, 2.3, 2.8, 3.6, 5.7, 6.4, 7.1, 7.2, 11.2, 12.1, 12.2, 12.3, 12.4, 12.5, 12.6_

- [ ] 2.4 `help` の語を任意の深さに対応させ、ヘルプの優先の範囲を末端コマンドに揃える
  - 子を持つコマンドの走査中に `help` を見たら、後続のトークンを子コマンド名として順にたどり、たどり着いたコマンドのヘルプの要求を返す（2.2 で移した 1 段だけの扱いを置き換える）
  - 名前が一致しない場合と、末端コマンドに達した後に引数がある場合は、段を `help` を見た時点まで戻してから誤りとする（接頭辞と案内は `help` を書いたコマンドの経路になる）
  - `help` の語に関する dispatch スイートの既存の期待値のうち、文面が変わるもの（`too many arguments for 'help'` は `unknown command` または `unexpected argument` になる）を直す
  - 回復走査を、誤りを検出した時点で選択中のコマンドが末端コマンドである場合に働かせる（末端コマンドのルートを含む）。子を持つコマンドが選択中の誤り（未知のサブコマンド、子コマンドの選択前の未知のオプション、`help` の語の誤り）では、後ろに `--help` があっても誤りを報告する
  - 完了時: `tool help`、`tool help copy`、`tool help nope`、`tool help copy x`、`nest help remote add`、`nest remote help add`、`nest help remote bogus`（`nest: unknown command 'bogus'`）、`nest help status x`（`nest: unexpected argument 'x'`）、`tool bogus --help`・`tool --bogus -h`・`tool help nope --help`・`nest remote bogus --help`（いずれも使い方のエラーのまま）、`single --bad --help`（ルートコマンドのヘルプ）、`nest remote add --bad --help`（`add` のヘルプ）のテストが、dispatch、errors、nested、single の各スイートで合格する。診断は常に 1 件である
  - _Boundary: Parser_
  - _Requirements: 7.4, 8.3, 8.4, 8.5, 8.6, 8.7, 8.10_

- [ ] 2.5 コマンドのヘルプを 1 つの書式に統合する
  - 全体用とサブコマンド用の 2 つの書式をやめ、コマンドの性質で要素を決める: 子を持つコマンドは子コマンドの一覧（末尾に `help` の行）と末尾の案内、末端コマンドは位置引数、ルートコマンドは `--version` の行を持つ
  - 使い方の行に経路を出す。子を持つコマンドでは、有効なオプションがあるときだけ経路の直後に ` [<options>]` を出す
  - `Options:` に、そのコマンドのオプション、親から祖先へ向かう順の引き継いだオプション、`-h, --help`、（ルートコマンドでは）`--version` を並べ、列を揃える
  - 使い方の案内を、経路を使った `Run '<path> --help' for usage.` にする
  - 完了時: help スイートで、`tool` のルートコマンドと `build`・`copy`・`cat` のヘルプ、バージョン、案内が、改訂前の期待する文面から変えずにバイト単位で一致する。single スイートで `single --help` の文面（`Arguments:` と、`Options:` の `--version`）と案内 `Run 'single --help' for usage.`、nested スイートで `nest remote` のヘルプ（使い方の行の ` [<options>]`、`Commands:` の `add`・`remove`・`help`、末尾の案内）と案内 `Run 'nest remote --help' for usage.`、inherit スイートで `nest remote add --help` の `Options:` の順序（`--force`、`--token`、`--tags`、`--verbose`、`--config`、`-h, --help`）が、バイト単位の比較で合格する。同じ結果から 2 回生成した文面が一致する
  - _Boundary: HelpFormatter_
  - _Requirements: 2.4, 7.3, 9.1, 9.2, 9.3, 9.4, 9.5, 9.6, 9.7, 9.8, 9.9, 11.4_

- [ ] 3. 統合: monde-cli の追従
- [ ] 3.1 `monde` の宣言と解析結果の受け取りを新しい形に合わせる
  - `monde` の宣言を、説明と 4 つの子コマンドを持つルートコマンドとして、指示付き初期化子で書き直す。各サブコマンドのオプションと位置引数は、内容と順序を変えない。引き継ぐオプションは使わない
  - 状態ごとの振り分けを新しい取得関数と文面の生成に合わせる。ヘルプは標準出力へ、子コマンドの未指定は標準エラー出力へ書き、終了コードは変えない
  - 使い方のエラーの表示が解析結果を受け取り、経路の文字列を接頭辞として取り除いてから、案内の行を続ける
  - monde-cli のテストを新しい形に合わせる。期待値を変えるのは、設計書の「改訂前の 1 段の構成との違い」の表に当たるものだけとし、`monde bogus --help` が改訂前と同じく使い方のエラー（終了コード 2）になるテストを加える
  - 完了時: すべてのターゲットがビルドでき、`ctest -L cli` が合格する。各サブコマンドのハンドラ（extract、init、update、translate）のソースは変更していない
  - _Boundary: MondeCliAdapter_
