- [x] 2.4 必須かつ隠しの宣言と、別名の形と予約の誤りを検出する
  - 必須として宣言されたオプションを隠しオプションとして宣言したら、そのオプションと経路を示す宣言の誤りにする。隠しオプションだけの宣言（フラグ、単一の値、リスト値）は妥当とする。フラグに必須と隠しの両方を付けた宣言は、既存の「フラグは必須にできない」の誤りと合わせて 2 件を報告する
  - 別名ごとに、長い名前と同じ形の条件（空、先頭が `-`、`=` を含む）を検査し、誤りならその別名とオプションと経路を示す宣言の誤りにする。空文字列の別名の指定、先頭・末尾・連続のカンマは、空の別名として誤りにする
  - 別名が予約された名前（`help`、`version`）なら、その別名とオプションと経路を示す宣言の誤りにする
  - 形と予約の誤りは別名ごとに報告する。オプションの長い名前が形の誤りのときにも、別名の形と予約の検査は行う

- [x] 2.5 別名を含む名前の重複と、否定の形との衝突を検出する
  - 重複の検査を、長い名前どうしの比較から、長い名前と別名を合わせた名前どうしの比較に広げる。比べる相手は、同じコマンドの前に宣言されたオプション、同じオプションの前の名前（元の名前と前に書いた別名）、祖先のコマンドのオプション（引き継ぐかどうかによらない）とする
  - 否定の形との衝突の検査を、同じ名前の組み合わせに広げる。否定できるフラグの名前（元の名前か別名）`<n>` と、名前 `no-<n>` の組を、別のオプションとの間（同じコマンド、祖先と子孫の両方の向き）と、同じオプションの名前の間の両方で検出する
  - メッセージは既存の文面を使い、名前の位置に重複または衝突した名前を入れる。名前は長さを指定して出す。1 つのオプションについて、重複は最初の 1 件、衝突は最初の 1 件を報告する
  - 否定できないフラグと、別名 `no-<その名前>` を持つ別のオプションが並ぶ宣言、兄弟のコマンドどうしで同じ別名を持つ宣言は、妥当とする
  - 完了時: decl のスイートに、設計書の Testing Strategy の「別名の重複」「別名の衝突」「境界」の各テストがあり、合格する。別名を含まない宣言についての既存の decl と negate のテストは、メッセージの期待値を 1 バイトも変えずに合格する

## Implementation Notes
- CI（MSVC）: `f(g(&x), x)` の形は引数の評価順が規定されず、MSVC では `x` が先に評価される。`&x` で値を設定する呼び出しは、別の文で先に済ませる。（前の計画から引き継いだ注意）
- 1.1: 結果の値の `enabled` のコメントは、回数を記録するまでは設計書の文面（「count > 0 と常に一致する」）が事実に反するので、改訂前のままにした。2.1 で設計書の文面に差し替える。
- 1.2: 設計書は隠しオプションを `--jobs/-j <N>` としつつ「左列が `run` で最も長い」としていたが、両立しなかった（`--tags <TAG>[,<TAG>...]` が 27 桁）。値の表示名を `NUMBER-OF-WORKERS`（左列 30 桁）に直し、設計書も合わせた。ヘルプの左列の幅を見積もるときは、リスト値の `[,<VALUE>...]` の分を忘れないこと。
- 1.2: `ext` の説明の文面は設計書にないので、実装で決めた（`test_decl.c`）。2.2 のヘルプの期待値はこの宣言に従う。新しい 3 つのスイートは、`negate_test.c` と同じ形の小さな補助関数（`run_parse` など）をファイルごとに持つ。`ext` の宣言の検査のテストは hidden のスイートにある。
- 2.1: 別名と元の名前を混ぜた出現回数のテスト（`ext -v --chatty run --token t --verbose` で 3）は、別名の照合が要るので 2.3 に送った。`count_test.c` には、プログラムを引数に取る補助関数 `run_parse_with` がある。
- 2.2: ヘルプに出すオプションかどうかの判定と、その数を数える関数は `clopts_help.c` の中にある。`clopts_effective_count` は隠しオプションも数えるままである。`solo` の文面（ルートの説明なし、`state` の概要）は設計書にないので、実装で決めた。
- 2.3: 名前を番号で取り出す関数 `option_name_at`（0 番目が長い名前、空の別名も 1 つの名前として返す）が `clopts_decl.c` にあり、いまは照合だけが使う。2.4 と 2.5 の検査はこれを使う。別名の形の検査が入るまでは、空の項目を含む別名（`""`、`"a,,b"`、`",a"`、`"a,"`）を持つ宣言で `--=x` がそのオプションの指定として通る。2.4 で、この 4 つの形が宣言の誤りで止まることを必ず確かめる。
- 2.4: 既存のテスト `deep_declaration_is_checked_without_depth_limit` に、オプションの構造体をゼロで初期化する 1 行を足した（期待値は変えていない）。このテストは構造体の一部のメンバーだけを設定していて、改訂前から未初期化の `negatable` と `default_enabled` を読んでいた。別名の検査が未初期化の `aliases` を読んで落ちたため直した。リポジトリの中で、ゼロで初期化せずに使う `clopts_option_t` はここだけである。
- 2.4: 別名の誤りは、長い名前の検査の直後、短い名前の検査の前に報告される。形が誤りの別名には、予約の検査をしない。`clopts_decl.c` には、名前の長さを `int` に収める `name_precision` と、名前と文字列を比べる `name_is` がある。
- 2.5: 設計書にない点を実装で決めた。形または予約の誤りで弾かれた別名は、重複と衝突の比較に加えない（`","` は「空の別名」の誤り 2 件だけになる）。長い名前が形の誤りのときに重複を見ない既存の扱いに揃えた。同じコマンドの中の重複を報告したオプションは衝突の検査を飛ばし、祖先との重複では飛ばさない（改訂前と同じ）。重複と衝突の誤りは、別名の形の誤りより先に報告される。
