# Brief: yaml-front-matter

## Problem
Markdown 文書の YAML フロントマターには、`title` や `description` など翻訳すべき値が含まれる。指定したキーの値だけを抽出し、訳文に置き換えても周囲の YAML をバイト単位で保つ必要がある。外部の YAML ライブラリは使えない。

## Current State
YAML パーサはまだない。

## Desired Outcome
- 文書先頭のフロントマターを検出できる。
- フロントマターでよく使われる YAML のサブセットを解析し、キーパスごとにスカラー値とそのソース範囲を返す再利用部品がある。
- 訳文の書き戻しに必要な情報も返す。たとえば、引用符の種類や、ブロックスカラーのインデントである。

## Approach
- YAML サブセットに絞った手書きのパーサを実装する。
- スカラー値の論理値（アンエスケープ後の文字列）と、原文上の範囲・スタイルを両方保持する。
- 訳文を書き戻すときに、元のスタイルのまま安全に表現できるかを判断して整形する部品も提供する（例: 引用符のエスケープ）。

## Scope
- **In**:
  - `---` で囲まれたフロントマターの検出
  - マッピング、シーケンス（ブロック形式、可能ならフロー形式）
  - プレーン・シングルクオート・ダブルクオートのスカラー、ブロックスカラー（`|`、`>`）、コメント
  - キーパス（ネストしたキーを含む）によるスカラー値の参照
  - 書き戻し用の値の整形
  - 非対応の構文（アンカー、エイリアス、タグ、複数ドキュメント）の検出と報告
- **Out**:
  - YAML 仕様の完全な対応
  - どのキーを翻訳するかの判断と、CLI オプションの解釈（translation-units と monde-cli が担う）

## Boundary Candidates
- フロントマターの検出
- YAML サブセットの解析とデータモデル
- スカラー値の書き戻し時の整形

## Out of Boundary
- TOML フロントマターなど、YAML 以外の形式
- YAML 全体の再シリアライズ

## Upstream / Downstream
- **Upstream**: project-foundation
- **Downstream**: translation-units

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: markdown-parser（フロントマターの後ろの本文の開始位置を受け渡す）

## Constraints
- 非対応の構文を見つけたときに、エラーにするかそのまま出力するか（Q3-2）を要件で確定する。
- キーパスの指定方法（例: ネストしたキーの区切り文字）を、monde-cli のオプション仕様と揃える。
