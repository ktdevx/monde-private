## Implementation Notes
- 1.1: `tests/tu` から spec_reader を使うときは `#include "../markdown/spec_reader.h"`（相対パス）。`monde_add_module_tests` に include ディレクトリの指定がないため。
- 1.1: `struct mnd_tu_doc` は配列の伸長のために `seg_cap` を持つ。抽出の仮の実装は `out` を変えずに false を返す（失敗時に呼び出し前の件数へ戻す規約を優先）。
- 2.1: Scanner は `mnd_tu_collect_front_matter` が診断なしで false を返したときだけ `out of memory` を補う。2.3 では不正なキーパスは上流の診断で、メモリ不足は診断を加えずに false を返すこと（`mnd_tu_collect_markdown` の false は常にメモリ不足として扱われる）。valgrind が使える（`valgrind --leak-check=full --error-exitcode=1 build/tests/tu/tu_tests`）。
- 2.2: 2.1 の Scanner のテスト（front_matter_test.c）は Markdown のセグメントの実数を期待する形に更新済み。キーを指定するテストは最後のセグメントの msgid で確かめているので、2.3 でフロントマターのセグメントが先頭に加わっても壊れない。spec.txt の全例（LF / CRLF / CR）で範囲が原文内・昇順・重なりなし・末尾が空白でないことを一時的なテストで確認済み。
- 2.3: 上流の `mnd_yaml_path_find` は path の引数を持たないため、`invalid key path "%s"` と照合中の `out of memory` の診断は path が NULL になる。design は上流の診断を「そのまま」通すと定めており、7.6（すべての診断に呼び出し側のファイル名）と食い違う。tu の範囲では補正しない（foundation の内部に依存するため）。5.3 で人の判断を仰ぐ（foundation に path を補う API を足す / yaml の API に path を足す / 7.6 にキーパスの診断の例外を明記する、のいずれか）。
- 3.1: 抽出の失敗時は、追加したエントリの解放に加えて、既存のエントリに足した参照と抽出コメントも呼び出し前の件数に戻す（公開ヘッダの「呼び出し前の状態に戻す」を満たすため）。po は素の malloc で失敗の注入口がないため、メモリ不足の経路は一時的な注入ハーネスで確認した（コミットしていない）。
- 4.1: Splicer は失敗時に `out` を呼び出し時の長さに戻す（`mnd_buf` に切り詰めの API がないため po と同じく `len` と NUL を直接書く）。`mnd_tu_splice_front_matter` は詰め物の確保の失敗では診断なしで false を返し、整形の失敗では上流の診断がある。4.3 の Rebuilder は「診断が増えずに false なら `out of memory` を補う」こと。`mnd_tu_splice_markdown` の false は常にメモリ不足。
- 4.2: 構造の検査は表の順（全行の空行 → ATX の改行 → 全行のブロックの開始）で判定する。行は `\n` だけで分け、末尾の `\n` や空の訳文は空行として検出する。記号の後ろの「空白」にはタブを含める（CommonMark に合わせた）。`text` に NULL を渡さないこと。
- 4.3: 構造の検査の警告 `translation line %zu` は 1 起点（`mnd_tu_check_structure` の 0 起点の行番号 + 1）。`mnd_tu_extract` で作ったカタログには msgstr の要素がないので、msgstr = msgid のカタログを作るテストは要素を自分で足す。
