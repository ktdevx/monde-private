## Implementation Notes
- 1.1: Ucd の表の形式（`mnd_po_ucd_range_t` と `mnd_po_ucd_lb_ranges` / `mnd_po_ucd_width_ranges` とその件数）は `po_internal.h` で定義した内部の形式で、1.2 で変えてよい。SA → CM の解決に必要な一般カテゴリ Mn・Mc の判定は、設計の宣言にないため 1.2 で内部の関数として追加する。
- 1.2: UCD 15.0.0 で U+FFFC が CB のため、`MND_PO_LB_CB` を XX の後ろに追加した。2.4 で CB を解決・処理する（UAX #14 LB20、libunistring 1.1 の扱いに合わせる）。Mn・Mc の判定は `mnd_po_ucd_is_mark`。生成コマンド: `python3 -I tools/gen_po_ucd.py <ucd>/LineBreak.txt <ucd>/EastAsianWidth.txt <ucd>/extracted/DerivedGeneralCategory.txt -o src/po/po_ucd_tables.c`。文字幅は libunistring 1.1 の `uc_width` と 386 個のコードポイント（Unicode 15.0 の新しい絵文字、CJK のブロック内の未割り当て、U+D7B0〜U+D7FB、U+00AD など）で異なる。正解ファイルと合わない場合は 6.1 で扱う。
- 2.1: `mnd_po_find_duplicate(catalog, from, &first, &second)` は、`from` 以上で先に同じキーの有効なエントリがある最小の `second` と、その最初の定義 `first` を返す。すべての組は `from = second + 1` で繰り返して列挙する。`mnd_po_flag_remove` は一致するフラグをすべて削除する。
- 2.2: `mnd_po_header_set` は `:` から値までを `": "` に正規化する。`mnd_po_date_format` は書式の桁に収まらない値（年が 0〜9999 の外、オフセットが 99:59 超など）で false を返す。
- 2.3: 8 進数の値が 255 を超える `\400`〜`\777` も BAD_ESCAPE とする（gettext 0.21 は黙って切り詰める）。`bad_offset` はリテラルの内側の先頭から数えた `\` の位置で、Reader は `bad_offset + 1 < len` を確かめてから次の文字を読む。失敗時は `out` の長さを呼び出し前に戻す。
- 2.4: 分割の機会は libunistring 1.1 の `u8_possible_linebreaks_v2` と一致させた（CB → ID、LB29 を適用しないなど、UAX #14 との違いはコードに注記）。唯一の違いは設計どおり SA の Mn・Mc を CM とする点（libunistring は AL）。LB30b の表（Extended_Pictographic かつ未割り当て、35 範囲）は UCD 15.0.0 の emoji-data.txt から導いて `po_linebreak.c` に手で置いた。Unicode を上げるときは作り直す。改行（BK・CR・LF・NL）の前後は 0 で、強制改行は Wrap（4.1）が扱う。
- 3.1: 参照の `file:0` と桁あふれする行番号は、語全体をファイル名にして行番号を 0 とする（設計の文言からの逸脱。msgcat 0.21 は `g.c:0` をそのまま出力するので、往復が一致する）。U+2069 の後ろの `:数字` だけを行番号とし、対応のない U+2068 は除く。ファイル名が空の参照（`:5`、`⁨⁩` など）の扱いは未決で、3.3 か 6.1 で決める。字句（`mnd_po_read_lex*`）と組み立て（`mnd_po_read_assemble`）は分けてあり、3.2 は組み立てを状態機械に差し替える。
- 3.2: 不正な遷移はすべて `mnd_po_read_invalid(reader, line, fault, expected)`（`mnd_po_read_fault_t`）を通る。現在は最初の誤りで解析を止めるので、3.3 で回復に置き換える。設計で名前のない誤り（続き先のない文字列、msgstr の後の msgstr）は仮に `missing msgid` としている。msgid と msgstr の間の空行は設計どおり誤り（msgcat は受け付ける）。`#|` の後のコメントと、`#|` のキーワードを繰り返したときの上書きは受け付けている（msgcat は誤りにする）。gettext が作った実際の PO で、msgexec と同じ内容に読めることを確かめた。
- 3.3: エラーの後は次の空行・コメント（`#|`・`#~|` を含む）・`msgctxt`・`msgid`（`#~` 付きを含む）の行から再開する（行頭だけで判定し、読み飛ばす行は字句解析しない）。状態機械の誤りを見つけた行が再開の行なら、前のエントリだけを捨ててその行から新しいエントリを始める（1 回だけ。字句の誤りの行は消費する）。読み込み後の検査は 重複→charset→改行 の順にすべて行い、改行の不一致の警告の行番号はエントリの開始行。ファイル名が空の参照の扱いは 6.1 で決める。
- 4.1: Wrap の API は `mnd_po_wrap_string(prefix, keyword, s, len, wrap, eol, out)`（各行の後ろに eol を付けて out に加え、失敗時は長さを戻す）。4.2 は no-wrap のとき wrap=false を渡す。設計どおり実装したが、msgcat 0.21 と 2 点異なる（6.1 で直す）: (1) 区切れない 79 桁超の区分が 1 つだけなら msgcat はキーワードの行に書く（`msgid ""` にしない）。(2) msgcat は分割の機会をエスケープ後の文字列で求め、エスケープの内部と `\n` のエスケープの直前を禁止する（エスケープを含む乱数の文字列の約 10% で差が出る。エスケープのない文字列では一致）。
